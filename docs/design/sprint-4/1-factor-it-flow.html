Order and timing

  • 0 msLast step done. Step card fades out (150 ms) as the header facts and the Summary fade in (200 ms).
  • 60 msPrice, then 60 ms later Drawdown. Each panel replaces its own placeholder, one after another, top to bottom.
  • +60 ms eachPanels 4 to 8 follow the same way. The reveal ends about 620 ms after the data arrives.
  • 480 msEvery panel below the eighth swaps with no animation, out of sight.
  • No jumpA revealed panel never moves: everything under it is still a placeholder when it appears. The panel fades and rises 6 px by transform only, so the layout does not change.

Live replay

Four panels fade in top to bottom, 60 ms apart. With reduced motion switched on in the system, they appear at once.

Re-run: the old report stays, dimmed

A new run while a report is on screen keeps that report (SPY here) at 60 % opacity. A 3 px bar sticks to the top of the page and a small chip says which request is running and at which step. The old report is not clickable. The sidebar already shows the new ticker (QQQ). There is no placeholder page and no step card, so nothing jumps.

Error: what happened, and what to do next

First run: the error replaces the placeholder page. It keeps the ticker as the page heading, says what happened in one sentence, says what to do in a second sentence, and offers Try again and Change ticker. The step card stays below and marks the step that failed; later steps read Not run. Focus moves to the message, which is announced at once.

    g

    Cached report: opens at once, no steps

    When the server already holds this exact report, the start call says so and the report is fetched and drawn straight away: no step card, no placeholder page, no fade. The button is busy for the length of that fetch only, normally under 300 ms, and returns to Factor it. The only trace is the sidebar section list appearing.
