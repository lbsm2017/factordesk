# Decision: report density, width cap and range controls

Date: 2026-11-18
Status: Decided-pending-implementation

## In one sentence

The report keeps one narrow column with few, short numbers per panel, says plainly which days are not analysed, and leaves the date range and ticker pickers to the dashboard, because a static file cannot recompute the statistics.

## What we decided

- The content column is at most 1216 px wide and centred, even on a 1920 px screen. Number columns have a fixed width, and a table that looks sparse loses a column instead of stretching the others.
- The header has one line of title and two small chips (when the factor data ends, and the number of warnings), then one range line. The data-quality notice is two plain lines with a "Details" disclosure for the technical text.
- The headline strip has five cells: alpha, R², residual volatility, observations, and the analysed range. Each has a value and at most one short line.
- Method detail in panel footnotes folds into a "How this is computed" disclosure. It opens by itself in print.
- The price chart shades days that are not analysed at both ends, draws a dashed line at each cut, and labels it "Not analysed: factor data ends 30 Sep 2026".
- Factor-exposure marks are smaller: interval caps 3 px tall (dropped on very narrow intervals) and a 7 px diamond for the average rolling beta, centred on the bar.
- Date range and ticker pickers are designed for the dashboard only: range chips YTD, 1Y, 3Y, 5Y and Full history, a custom start and end, a ticker search, and an always-visible "analysed range" label. The static report states its range and has no controls.

## Why

The owner reviewed the live report and found it too wide, too spread apart and too dense to read, and asked for a range picker and a ticker selector. We found the live page used a 1680 px column and monospace type everywhere, while the design spec said 1216 px and Instrument Sans, so part of the problem was drift from the spec. The rest was real: six headline cells with two lines each, three badges and a long warning paragraph all sat above the first chart.

A range picker has to rerun the regression, and the report is one offline file with no server (see the application stack decision). We rejected two ways of faking it. Embedding a precomputed regression for each preset would make the file about five times larger and still allow no custom dates or ticker change. A local server for the report would give up the double-click-to-open promise. The owner chose to design the controls for the dashboard, which is already on the roadmap.

We rejected widening the shaded stretch after the factor data ends so that it is easier to see. The chart is a time axis, so a wider band would misstate how many days are missing; the dashed line and the label do that job instead. We dropped "Factor lens history" from the preset list because the owner kept their own list.

## How it works

- The prototype in `docs/design/prototype/` is regenerated by `build_prototype.py` (add `--controls` for the dashboard mock). Screenshots at 1920, 1440 and 390 px, light and dark, are next to it.
- Measured on the prototype: content width 1216 px at both 1440 and 1920 px; no sideways scrolling at 390 px; print is still 8 pages.
- Chips that cannot work for a ticker (for example 5Y on a stock with two years of history) are disabled, and the reason is written under the strip instead of hidden in a tooltip.
- The dashboard needs `ticker`, `start` and `end` parameters on the report endpoint. The endpoint file is empty today.

## What it costs us

- The live renderer still has the old layout until the checklist in the design document (section H.12) is ported. The screenshots show the target, not the shipped page.
- A plain-language warning summary needs a new `summary` field next to each warning message, or the renderer keeps a lookup by warning code (the prototype does this).
- The minimum number of days behind each range chip is not fixed yet. The mock uses 252, 756 and 1260 trading days; the real thresholds come from the pipeline.
- Folding method text hides it from a quick skim. Readers who want the test names must open the disclosure.
- Not verified as of 2026-11-18: screen readers, Firefox and Safari. Print was checked in Chrome only.

## What would change our mind

Readers who need to try other dates without a server would justify a lightweight local serve command. If users report missing the folded method detail, we would show one more sentence by default.

## Update, 2026-11-19: dashboard defaults

On 2026-11-19 the owner set the dashboard defaults to 10Y and FF6. The API default stays FF5. Under FF6 the five FF5-only sections are hidden.

A URL without `range` opens on 10Y and a URL without `model` opens on FF6. The URL writes a value only when it differs from the default: `model=ff5` for FF5 and `range=FULL` for full history. Old URLs with explicit parameters keep their meaning. The dashboard always sends `model` to the API, so a request without `model` (a script, the static report) still gives FF5.

On 2026-11-19 the owner asked for a more compact range summary in the sidebar. The paragraph under the From and To fields is now a thin timeline of the whole price history: a muted part before the analysed window, a solid cyan part for the window, and a hatched part for the price days after the factor data end. One line below it gives the dates and the size of the window ("3 Oct 2016 → 30 Sep 2026 · 2,512 days"; months for a track record, which now shows the same summary). The full sentences, and the reasons a preset cannot be chosen, sit in a "Details" disclosure, and a one-line note names the presets that need more history. Nothing was removed and the backend is unchanged.

## Update, 2026-11-19: Alpha across models and World beta share a row

The owner found the two panels too spread out across the full width. From 1280 px they now sit side by side in two equal halves, the same way Price and Drawdown do; under 1280 px they stack. With "Show statistics" on, World beta takes the full row because it then has six columns.

Both panels are compact. Alpha across models shows Model, Alpha a year, t and adjusted R², with a dot per row and an approximate 95% range (alpha plus or minus 1.96 times |alpha / t|) on one shared scale with a line at zero. Plain R², the long model note and the dropped-row count moved into "How this is computed". World beta keeps its forest plot with a narrower label column and axis; the stand-in notes, the data end dates and the shorter-span sentence moved into "How this is computed". Nothing was removed.

## Update, 2026-11-19: the model selector is gone

On 2026-11-19 the owner removed the FF5/FF6 selector from the sidebar. The dashboard uses FF6. A `model=ff5` URL still opens FF5. A Settings module will hold the choice later.
